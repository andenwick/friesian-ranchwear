# ADR NNNN: Short decision title

- **Status:** Proposed
- **Date:** YYYY-MM-DD
- **Owners:** Names or roles
- **Related:** Issue, pull request, incident, or document links
- **Supersedes:** None

## Context

Describe the problem, relevant constraints, current behavior, and why a decision is needed now. Include production facts and domain invariants that materially limit the options.

## Decision

State the decision directly. Describe the boundary, ownership, data flow, and behavior that future implementation must preserve.

## Alternatives considered

### Alternative name

Explain the option and why it was not selected. Distinguish evidence from assumptions.

## Consequences

### Benefits

- Expected positive outcome.

### Costs and risks

- Known cost, limitation, or failure mode.

## Rollout and migration

Describe compatibility requirements, sequencing, data migration, feature flags, and the point at which the old path can be removed.

## Rollback and recovery

Describe how to stop or reverse the change safely, including any irreversible data effects.

## Validation

List the automated tests, production signals, and acceptance checks that prove the decision was implemented safely.
